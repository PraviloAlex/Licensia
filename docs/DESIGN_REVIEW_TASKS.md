## Диагноз (почему темы «где-то хорошо, где-то плохо»)

Факты из `src/styles.css` (9509 строк):

1. **Две конкурирующие светлые палитры.** `[data-theme="light"]` объявлен ДВАЖДЫ:
   - строка ~4688 — холодная сине-серая палитра (`--bg: #f0f4f8`, `--blue: #2a5fc4`);
   - строка ~4773 — тёплая оранжевая (`--bg: #F2F2F2`, `--blue: #D4641A`).
   Вторая побеждает по каскаду, первая — мёртвый код и мина: любой сдвиг порядка/спецификности меняет всю светлую тему.
2. **600 селекторов `[data-theme="light"] ...`** — ручные заплатки на каждый компонент. Каждый новый блок UI надо стилить дважды; забыли — получили «где-то плохо».
3. **977 захардкоженных hex-цветов** — они не переключаются с темой вообще.
4. **Два семейства токенов**: старое (`--bg`, `--blue`, `--text-hi`) и новое семантическое (`--s-bg`, `--s-accent`, `--s-text`). Страницы смешивают оба.
5. **Семантическая ловушка**: в светлой теме `--blue` = оранжевый `#D4641A`. Имя токена лжёт.
6. **Инлайн-цвета в TSX**, минующие темизацию: `VocabularyPage.tsx` `STATE_STYLES` (rgba-борды карточек), `PracticePage.tsx:642` (`rgba(255,255,255,0.07)` в conic-gradient — на светлом фоне почти невидим).
7. `<meta name="theme-color" content="#0a142e">` в `index.html` — всегда тёмный, даже в светлой теме (цвет статус-бара на телефоне).

Целевая архитектура (к ней ведут задачи фазы 2):
- компоненты используют ТОЛЬКО токены;
- `[data-theme="light"]` переопределяет ТОЛЬКО токены — один блок на весь файл;
- количество селекторов `[data-theme="light"] .класс` стремится к нулю.
